# 📐 15 — Конвенции разработки

> [!abstract] О чём эта заметка
> Правила, которых придерживается кодовая база: структура фич, алиасы путей, работа со стилями, логирование, линтеры и git-процесс. Следуйте им, чтобы новые части выглядели «как родные».

## 🗂️ Структура новой фичи

Каждая фича в `feature/<name>/` повторяет одинаковый скелет:

```
feature/my-feature/
├── screens/        # экраны (толстые компоненты, логика здесь)
├── components/     # приватные компоненты фичи
├── api/            # запросы к бэкенду этой фичи
├── styles/         # *.styles.ts рядом с экранами
├── types/          # api.types.ts и локальные типы
├── store/          # опционально: zustand-стор шагов/формы
├── hooks/          # опционально: кастомные хуки
└── assets/         # локальные картинки/иконки фичи
```

Роут в `app/` остаётся тонким: только импорт экрана из фичи и опции презентации ([[04 Роутинг и экраны]]).

## 🔤 Алиасы путей

Алиас `@/*` → корень проекта (настроен в [`babel.config.cjs`](../../babel.config.cjs)):

```ts
import { colors } from "@/styles/Colors";
import apiClient from "@/api/client";
import { useDeckStore } from "@/store/deck.store";
```

Всегда используйте `@/`, а не относительные `../../..`.

## 🎨 Стили

1. Цвета — только из [`styles/Colors.tsx`](../../styles/Colors.tsx); типографика — компонент `<Typography>` ([[13 UI-кит и стили]]).
2. Стили экрана живут в отдельном файле `xxx.styles.ts` рядом с экраном.
3. Общие паттерны — `commonStyles` из [`styles/Common.tsx`](../../styles/Common.tsx).

## 🌐 Работа с сетью

- Все запросы — через единственный `apiClient` ([[05 API слой]]); URL строится хелперами `getMainServiceApiUrl()` / `getAuthApiUrl()`.
- Каждая API-функция обязана: взять токен из `useAuthStore.getState().accessToken`, при отсутствии бросить ошибку, обернуть catch в `handleApiError(err, "человеческое сообщение")`.
- Токен добавляется заголовком `Authorization: Bearer <token>`; refresh происходит автоматически.

## 🧠 Состояние

- Глобальные данные (колоды, карточки, профиль, токен) — только через сторы `store/`; мутации колод — оптимистичные с rollback ([[06 Состояние и кэш]]).
- Локальное состояние формы шага — отдельный zustand-стор внутри фичи (как `register.store.ts`).
- Экраны читают данные через хуки `useDecks` / `useCards`, а не напрямую из сети.

## 🪵 Логирование

Проект использует консольные логи с эмодзи-маркерами — по ним удобно фильтровать отладку:

| Маркер | Значение |
| --- | --- |
| 🌐 | исходящий запрос |
| ✅ | успех |
| ❌ | ошибка |
| 💾 / 📦 | запись/чтение кэша |
| 🚨 | инвалидация кэша |
| ⚠️ | предупреждение (мягкий сброс формата) |

Пример: `[useDecks Cache Check] Проверка памяти. До 4 утра осталось N секунд.`

## 🧹 Качество кода

| Инструмент | Конфиг | Запуск |
| --- | --- | --- |
| ESLint 9 (flat config) + typescript-eslint + react/react-native plugins | [`eslint.config.js`](../../eslint.config.js) | `npm run lint` / `lint:fix` |
| Prettier | через eslint-plugin-prettier | `npm run format` |
| Husky + lint-staged | блок `lint-staged` в [`package.json`](../../package.json) | автоматически на commit |

Правило коммита: изменённые `.js/.jsx/.ts/.tsx` автоматически проходят `eslint --fix` и prettier; коммит падает при неисправимых ошибках.

## ✅ Чек-лист перед PR

- [ ] Новая фича лежит в `feature/` со стандартным скелетом; роут в `app/` тонкий.
- [ ] Нет хардкода цветов/шрифтов — используются токены.
- [ ] Запросы идут через `apiClient` + `handleApiError`.
- [ ] Данные попадают в сторы/кэш по правилам [[06 Состояние и кэш]].
- [ ] `npm run lint` и `npm run format` без ошибок.
- [ ] Если менялся `lexical-editor/` — пересобран и обновлён `shared/generated/lexicalHtmlString.ts` ([[09 Редактор карточек]]).
